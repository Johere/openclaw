## Tooling
Structured tool definitions are the source of truth for tool names, descriptions, and parameters.
Tool names are case-sensitive. Call tools exactly as listed in the structured tool definitions.
If a tool is present in the structured tool definitions, it is available unless a later tool call reports a policy/runtime restriction.
TOOLS.md does not control tool availability; it is user guidance for how to use external tools.
For follow-up at a future time (for example "check back in 10 minutes", reminders, run-later work, or recurring tasks), use cron instead of exec sleep, yieldMs delays, or process polling.
Use exec/process only for commands that start now and continue running in the background.
For long-running work that starts now, start it once and rely on automatic completion wake when it is enabled and the command emits output or fails; otherwise use process to confirm completion, and use it for logs, status, input, or intervention.
Do not emulate scheduling with sleep loops, timeout loops, or repeated polling.
For non-trivial multi-step work, keep a short plan updated with `update_plan`.
Skip `update_plan` for simple tasks, obvious one-step fixes, or work you can finish in a few direct actions.
When you use `update_plan`, keep exactly one step `in_progress` until the work is done.
After calling `update_plan`, continue the work and do not repeat the full plan unless the user asks.
If a task is more complex or takes longer, spawn a sub-agent. Completion is push-based: it will auto-announce when done.
For requests like "do this in codex/claude code/cursor/gemini" or similar ACP harnesses, treat it as ACP harness intent and call `sessions_spawn` with `runtime: "acp"`.

Set `agentId` explicitly unless `acp.defaultAgent` is configured, and do not route ACP harness requests through `subagents`/`agents_list` or local PTY exec flows.

# 4) 这一轮典型多步输出 (示例, 不是硬编码)
================================================================================

因为 system prompt 的 `## Memory Recall` 段明确要求:
  "Before answering anything about ... people, preferences, ... run memory_search"
Qwen3 / Claude / GPT 这类指令跟随能力强的模型, 看到 "what do you know me?"
基本都会先打一发 memory_search. Pi Embedded Runner 的 turn loop 会:

  Turn 1 (LLM → assistant):
    tool_calls: [
      {
        "id": "call_001",
        "type": "function",
        "function": {
          "name": "memory_search",
          "arguments": "{\"query\":\"user identity preferences role background\"}"
        }
      }
    ]
    content: ""   (Qwen3 可能还会夹带 <think>...</think>, 见文末备忘)

  Turn 1.5 (OpenClaw runs memory_search(...) locally, 把结果回灌):
    role: tool
    tool_call_id: call_001
    content (JSON 字符串, 真实结构见 extensions/memory-core/src/tools.ts):
      {
        "results": [
          {
            "path": "MEMORY.md",
            "startLine": 3,
            "endLine": 5,
            "score": 0.91,
            "snippet": "- User is a C++/Python dev with LLM/VLM background.\n- Currently deploying OpenClaw + Feishu channel on local vLLM.\n- Prefers terse, concrete, code-first answers.",
            "source": "memory",
            "corpus": "memory"
          },
          {
            "path": "memory/preferences.md",
            "startLine": 1,
            "endLine": 2,
            "score": 0.78,
            "snippet": "Timezone Asia/Shanghai. Primary working dir /mnt/disk1/projects/openclaw.",
            "source": "memory",
            "corpus": "memory"
          }
        ],
        "provider": "openai",
        "model": "text-embedding-3-small",
        "fallback": null,
        "citations": "auto",
        "mode": "semantic"
      }

  Turn 2 (LLM → assistant, 最终回复, SOUL.md "Claw" persona 风格):
    content: "[[reply_to_current]] Hey Lin. What I've got:
              - C++/Python → LLM/VLM infra.
              - Currently on OpenClaw + Feishu, self-hosted vLLM (qwen3.5-35b-a3b).
              - Prefers terse, code-first replies; Asia/Shanghai.
              - Workspace: /mnt/disk1/projects/openclaw.
              Source: MEMORY.md#3-5"

- 前缀 [[reply_to_current]] 会被 reply-dispatcher 识别并去掉,
  Feishu 侧以原生 reply 形式引用 "hi, what do you know me?".
- Citations 句尾的 `Source: MEMORY.md#3-5` 来自 `## Memory Recall` 段
  "include Source: <path#line>" 的引导, 不是硬编码格式.
- 如果 memory_search 返回 `disabled: true` (例如 embedding provider 429 了),
  prompt 要求模型显式告知用户 "memory retrieval is unavailable" —— 不能假装
  什么都不知道, 也不能瞎猜.

⚠️ Qwen3 系列推理输出注意事项 (reasoningTagHint=false 下, 与纯 "hi" 那份相同):
  - Qwen3 的 Instruct/Thinking 模型默认会把内部推理直接写进 assistant
    content (甚至会在 tool_call 之前夹一段 <think>...</think>). 因为没有
    tagged 模板引导, OpenClaw 也不会自动剥离 <think> 段.
  - 在 Feishu 里这些 <think> 块会作为普通消息内容发给用户. 常见做法:
      1) 关掉模型的 thinking (部分 Qwen3 支持 /no_think 系统指令),
      2) 或在 workspace 挂一个本地 provider 插件, 返回
         resolveReasoningOutputMode = "tagged" + 用 <final> 包裹最终答复,
      3) 或者自己在 reply-dispatcher 前做一次 <think>...</think> 清洗.
